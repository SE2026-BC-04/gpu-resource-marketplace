The main lesson was that one search parameter crosses multiple contracts. Adding `listing_id` only to the screen could look correct while pagination or authorization remained wrong. The filter therefore had to pass through the route, service, cursor context, reader port and SQL. A fixed baseline cursor and exact unfiltered SQL/parameter assertion made compatibility observable instead of relying on the word “optional.”

The RED runs failed for the intended reason: the route ignored the filter and accepted invalid values. After implementation, focused backend tests passed 109, while five PostgreSQL tests skipped. Frontend tests passed 160; typecheck and production build also succeeded. Removing one role-scope guard caused three cross-role assertions to fail. This mutation check adds evidence beyond a green suite, but tests only one guard. Three backend runs were stable, which does not prove PostgreSQL locking or browser timing reliable.

The main remaining uncertainty is environmental and cross-phase. Docker denied access, so real PostgreSQL and runtime E2E checks could not run. The 120-VU harness help was inspected, but no p95, throughput or error rate was measured. Coverage tooling and PDF renderers are absent. These remain evidence gaps; skipped tests and a successful build are not substitutes.
