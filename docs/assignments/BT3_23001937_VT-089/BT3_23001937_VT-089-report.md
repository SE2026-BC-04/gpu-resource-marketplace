## 1. Mục tiêu và thiết kế

VT-089 bổ sung tìm kiếm Job theo Listing vào `GET /api/v1/jobs`, có thể kết hợp với `status`, giữ nguyên authorization theo role, response DTO, thứ tự và cursor cũ. TV1 phê duyệt L2 `DEC-VT089-L2-01` và cho phép thay đổi contract, tests, implementation trong cùng PR. TV2 đưa `ACK_WITH_ACTIONS` cho hướng reader/query tại proposal HEAD; đây không phải ACK cho implementation SHA.

API Contract §8.2 trong PR quy định `listing_id` là tùy chọn, chỉ nhận UUIDv4 lowercase canonical. Giá trị rỗng/sai/noncanonical, uppercase, UUID không phải v4 hoặc query key lặp trả `400 INVALID_FILTER`. Không tra cứu Listing để phân biệt không tồn tại với không có Job nhìn thấy được; cả hai trường hợp trả trang rỗng `200`. Predicate visibility, status, listing và keyset nằm trong cùng SQL trước LIMIT. Unfiltered request giữ nguyên bytes/HMAC cursor, câu SQL và bound parameters baseline. Không có migration, index, dependency hay thay đổi Auth/Listings.

## 2. Thực hiện

Implementation đi qua router → service → cursor context → reader protocol → PostgreSQL adapter. Adapter thêm static SQL clause `j.listing_id = :listing_id` khi có filter và bind native UUID; không join Listing. Filtered cursor ký Listing ID canonical, còn context cũ không thêm `listing_id: null`. Frontend client và trang Jobs có filter Listing, reset cursor/history khi filter đổi và bảo vệ kết quả khỏi response cũ. Thêm tests unit/HTTP, recording-session SQL tests và một scenario runtime E2E có cổng PostgreSQL disposable.

RED được ghi trước implementation: run 01 có 7 lỗi đúng kỳ vọng, run 02 có 9 lỗi/2 controls pass, run 03 có 10 lỗi/2 controls pass/1 PostgreSQL skip. GREEN implementation nằm ở `e90627a`; full change history và logs được liên kết trong [README](README.md) và [traceability](traceability.md).
