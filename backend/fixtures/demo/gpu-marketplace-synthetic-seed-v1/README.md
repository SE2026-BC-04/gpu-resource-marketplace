# GPU Resource Marketplace — Synthetic Demo Seed v1

**Status:** draft data fixture, **not an executable SQL migration or DB installer**. Prepared for team review; no GitHub changes.

## Purpose

Provide project-owned **synthetic** identity, Worker, Listing and empty initial Job state for the Phase 1B–1E MVP. GPU models and mock prices are **fictional demonstration values** even when model names resemble real hardware. No live GPU, real merchant catalog, pricing API, actual personal information or payment data is used.

The approved **business rules and API/DB contracts are authoritative**. This fixture is *input data*, not a source of new requirements or rules. Outside GPU datasets can be consulted only for inspiration.

## Suggested provisioning sequence (not code)

1. **GPU-002** initializes role codes `roles` and implements the schema/migrations; only import after migration is reviewed and executed.
2. **GPU-003** provisions `users` from `identity_accounts_to_provision.json`, with *proper password hashes generated at provisioning time* using the approved Identity implementation; then provision `user_roles`. Never commit plaintext demo passwords or fake hashes. `DISABLED` account is used to test denial.
3. **GPU-002 / GPU-004** provision `workers`, zero `worker_reputation_aggregates`, then `gpu_listings`. Preserve ownership links and price strings as DECIMAL. `created_at`/`updated_at`/`assigned_at` originate from trusted server-side defaults, not client time.
4. **GPU-005** uses `job_api_scenarios_NOT_DB_SEED.json` via authenticated API. The API creates each QUEUED Job **and protected simulation reference atomically**. No Job rows are preinserted from this package.
5. **Worker key provisioning** remains separate from this demo dataset. Do not commit private signing keys or service tokens.

## Design rules this bundle respects

- Exactly 10 Phase-1 table names; Phase-2/3 tables are not introduced.
- User status `ACTIVE` / `DISABLED`; roles `CLIENT` / `WORKER` / `ADMIN`.
- Workers belong to accounts with `WORKER` role; listings belong to Workers.
- Listing statuses `ACTIVE` / `PAUSED`; GPU counts/VRAM positive; allocated=0 at startup.
- Mock price is a nullable decimal string with exactly two fractional digits; **not billing**.
- No runtime Job status, allocation, FIFO order or protected oracle is fabricated.
- Stable UUID **version 4** identifiers, NOT UUIDv5.
- Data tests are proposals, **NOT_RUN**, until approved implementation, schema and execution evidence exist.

## Open items / governance

- Exact deterministic simulation reference algorithm, version and test vectors (`DEC-P1-04`) need specific owner approval before implementing `TX-SUBMIT`.
- Authentication password hash algorithm and provisioning process must be agreed before seed import; no plaintext or hardcoded credential supplied.
- Idempotent replay on a subsequently PAUSED Listing needs contract review; this bundle avoids assuming an outcome for that case.
- If the team changes the **contract/schema** to fit synthetic values, stop and follow `docs/development/interphase-change-control.md` with both affected parties' ACKs. **Data values alone do not authorize architecture changes.**
